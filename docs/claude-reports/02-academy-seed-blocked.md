## Проверка

`prisma/schema.prisma:13-25`, enum `TaskCategory` содержит 11 значений:
`CHILDREN` (legacy), `SHOPPING`, `DELIVERY`, `QUEUE`, `HOUSEHOLD`, `ONLINE`, `CLEANING`, `DRIVER`, `MOVING`, `COOKING`, `PHOTO`.

Значения **`DIGITAL` нет**.

- Записи Center не создавались.
- Никакие файлы проекта не изменены.

## Контекст для решения

- Ближайшая существующая категория — `ONLINE` («Онлайн / Интернет», в UI `lib/categories.ts:9` подписана «IT задачи: сайт, дизайн, программа»). Все три трека (карточки маркетплейсов, монтаж видео, ИИ-инструменты) по смыслу ложатся в неё.
- Если добавлять `DIGITAL`: в Postgres это `ALTER TYPE "TaskCategory" ADD VALUE 'DIGITAL'` (отдельная миграция; в Postgres < 12 нельзя внутри транзакции, на Supabase Postgres 15+ — ок). Дополнительно придётся синхронизировать: `lib/categories.ts` (UI-справочник), zod-enum в `app/api/tasks/route.ts:13` (он и так отстал от схемы на 5 категорий — находка В16 в AUDIT.md), промпт AI-парсера в `lib/groq.ts`.
- Треки ссылаются на категорию через `Track.taskCategory TaskCategory` и `ExecutorCategory.category TaskCategory` — сид без валидного значения невозможен.

## Вопрос, требующий решения человека

Один из двух вариантов:
1. **Добавить `DIGITAL` в enum** — тогда: миграция на enum + правки `lib/categories.ts`, zod-схемы задач и промпта Groq (иначе категория будет «невидимой» для создания задач — повторение В16).
2. **Использовать существующую `ONLINE`** для всех трёх треков — без изменений enum, сид делается сразу.

После решения задача выполняется полностью по исходному ТЗ.
